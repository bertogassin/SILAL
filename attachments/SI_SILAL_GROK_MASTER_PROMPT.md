## 2. Жёсткий технологический контракт

### 2.1 Приложение — Rust 100% на прикладном уровне

Весь пользовательский код приложения, ноды-клиент, кошелёк, сеть, UI-логика, крипто-обвязка, синхронизация — **Rust (stable, edition 2021+)**.

Запрещено:
- писать бизнес-логику на JS/TS/Python/Kotlin/Swift как основной язык;
- Electron как основу;
- хранить seed/ключи в JS-рантайме.

Допустимо только:
- тонкие платформенные оболочки (Gradle/Xcode project, Info.plist, entitlements);
- декларативные UI-описания, если выбранный Rust UI-фреймворк так устроен;
- SQL / Ada исходники верифицируемого ядра данных.

Рекомендуемый стек UI (выбери и зафиксируй, не мешай три фреймворка):

**Предпочтительный вариант для «все платформы»:**
- Общее ядро: `si-core` (Rust)
- Десктоп (Windows / macOS / Linux): **Tauri 2 + Rust backend**, фронт минимальный; ещё лучше **Dioxus** или **Slint**, чтобы UI тоже был Rust.
- Android: Rust через `jni` / `uniffi` + тонкая Activity **или** Dioxus mobile, если стабильно.
- iOS / iPadOS: Rust через `uniffi` / C-ABI + тонкий SwiftUI host **или** тот же Dioxus.

Цель: один `si-core`, одни модели, один кошелёк, один движок древа.

### 2.2 Критическое ядро данных — Ada + SPARK 100%

Пользователь требует БД на Ada/SPARK. Правильная интерпретация (не пиши с нуля PostgreSQL на Ada за неделю):

Сделай пакет **`si-spark-engine`**:
- язык: **Ada 2012 + SPARK 2014**
- роль: формально верифицируемое ядро инвариантов, не «ещё один ORM»

Этот движок обязан доказывать (SPARK proof):
1. **Сохранение эмиссии SILAL:** сумма балансов + нераспределенный фонд + сожжённое = 10_000_000_000 (с учётом decimals).
2. **Неотрицательные балансы.** Никакой перевод не создаёт деньги.
3. **Идемпотентность перевода** по `tx_id`.
4. **Инварианты родства:**
   - рёбра только допустимых типов (parent, child, spouse, adoptive — явно);
   - нет циклов «предок самого себя»;
   - проверка общих предков по отцовской линии до N колен и материнской до M (N=9, M=5 по умолчанию, конфигурируемо);
   - результат калькулятора = `Allowed | Warning | BlockedByPolicy`, но **Blocked** только как предупреждение политики семьи, не как государственный запрет.
5. **Согласие живого человека** на появление в чужом древе: без consent-флага узел не публикуется другим.
6. **Целостность хешей документов:** нельзя подменить blob, не сломав hash-цепочку.

Хранение фактов:
- append-only журнал событий (event log) + снимки;
- на диске: зашифрованные страницы (см. крипто);
- доступ из Rust через стабильный C-ABI (`si_spark_engine.h`), без исключений через границу.

Ada/SPARK **не** заменяет сетевой индекс и полнотекст. Для этого в Rust: SQLite (SQLCipher) или redb/sled как кэш. Источник истины по критическим инвариантам — SPARK-движок.

### 2.3 Криптография сейчас и квантовый запас

Сейчас (MVP):
- подписи пользователей: **Ed25519**
- обмен ключами: **X25519**
- хеш: **BLAKE3** + **SHA-256** для совместимости с якорением
- AEAD: **XChaCha20-Poly1305**
- KDF: **Argon2id** для пароля хранилища
- мнемоника: BIP-39, деривация BIP-32/44 совместимая схема `m/44'/SILAL_COIN_TYPE'/0'/0/i`
- seed только в encrypted vault, never log, never screenshot-able в UI по умолчанию

Квантовый переход (заложить, не включать ломающим образом):
- Крипто-провайдер как trait: `Classic` | `Hybrid` | `PostQuantum`
- Hybrid phase 1: Ed25519 + **ML-DSA-65** (FIPS 204) на одну операцию
- PQ KEM: **ML-KEM-768** (FIPS 203)
- запасной долговременный: **SLH-DSA** (SPHINCS+)
- Формат адреса и транзакции версионированы: `addr_v1` (ed25519), `addr_v2` (hybrid), `addr_v3` (pq)
- Миграция: пользователь подписывает `MigrateAccount` обоими ключами, старый ключ помечается `legacy`
- Не обещай «квантово-неуязвимый блокчейн» в маркетинге MVP. Пиши: «криптоядро готово к гибридным подписям»

Зависимости только из аудируемых ящиков: `ed25519-dalek`, `x25519-dalek`, `blake3`, `chacha20poly1305`, `argon2`, `zeroize`, `secrecy`. PQ — через провайдер, который можно заменить.

### 2.4 Блокчейн — разумно, не «своя Ethereum с нуля в первую ночь»

MVP сети:
1. **Не запускай кастомный L1 в v0.1.** Это годы работы.
2. Сделай:
   - локальный детерминированный **dev-ledger** на SPARK-инвариантах (для демо кошелька и рефералки);
   - коннектор к существующему устойчивому L1 с токеном стандарта (Solana / Cosmos / Substrate — выбери ОДИН и обоснуй);
   - якорение хешей документов в публичную сеть раз в N часов (batch merkle root).
3. Когда продукт живой — отдельный спек **Si Chain**:
   - PoS с делегированием,
   - низкие комиссии,
   - supply cap в генезисе,
   - quantum-ready tx format.

Эмиссия: **ровно 10_000_000_000 SILAL**.  
Decimals: **6** (1 SILAL = 1_000_000 units).  
Никакого бесконечного минта после генезиса. Mint-ключ после распределения в timelock / multi-sig / burn.

## 3. Токеномика SILAL (10 млрд) — логичная и антискам

Распределение генезиса (зафиксируй в коде константами, не «потом поправим»):

| Фонд | Доля | Кол-во | Правило |
|---|---:|---:|---|
| Community & referrals | 30% | 3_000_000_000 | вестинг + anti-sybil |
| Ecosystem / grants / events | 20% | 2_000_000_000 | multi-sig совета |
| Treasury (развитие si) | 15% | 1_500_000_000 | 36 мес. vesting, cliff 6 |
| Early contributors | 10% | 1_000_000_000 | 24 мес. vesting, cliff 6 |
| Liquidity & market making | 10% | 1_000_000_000 | частично locked |
| Mediation & archive utility reserve | 8% | 800_000_000 | тратится на полезные действия |
| Insurance / bug bounty | 4% | 400_000_000 | только на инциденты |
| Genesis liquidity airdrop verified families | 3% | 300_000_000 | KYC-light / social attest, не продажа мечты |

Правила безопасности токена:
- никакого скрытого mint;
- комиссии прозрачны (по умолчанию низкая сеть + 0% на перевод другу внутри si в dev-ledger);
- реферал **не** является финансовой пирамидой: платит только фонд, один раз за квалифицированного пользователя, с капом на кошелёк;
- нельзя купить «статус хорошего человека» за SILAL;
- нельзя заблокировать чужой кошелёк приложением (только пользователь и его ключи).

### Реферальная программа (анти-абуз)

Условия начисления:
- реферер даёт код / глубинную ссылку `si://r/<code>`;
- реферал ставит приложение, создаёт кошелёк, проходит **человеческую** проверку (не продажу паспортных данных оптом): подтверждение живого аккаунта + опционально семейное поручительство;
- начисление **только после qualifying action**: 7 дней активности ИЛИ якорение первого документа ИЛИ участие в одном событии землячества;
- выплата: 70% рефереру, 20% рефералу (welcome), 10% фонду модерации антисибил;
- кап: не больше X SILAL на одного реферера в месяц;
- глубина: **1 уровень**. Никаких «10 линий», это пирамида — запрещено;
- сибил: один device attestation + одно дерево согласия + одинаковые паттерны режутся движком, апелляция через людей, не через автобан навечно.

## 5. Приватность, право, магазины

- GDPR-ready: согласие, экспорт, удаление, минимизация.
- Живой человек в чужом древе — только с его consent. Предки — по правилам семьи.
- Женский контур безопасности: скрытый профиль, семейный контакт, блок преследователя без публичного позора.
- Детские профили: только опекун, без публичной карты, без кошелька до возраста по закону страны.
- Приложение подчиняется закону страны проживания пользователя. Адат/шариат — обычай и личный выбор, не подмена суда.
- Для App Store / Google Play / Microsoft Store: обычная privacy policy, account deletion, нет «секретной полиции сообщества».

Модель данных чувствительного графа:
- E2E: ключи у пользователя;
- сервер видит только ciphertext + routing metadata минимум;
- searchable encryption не строить в MVP (это ловушка). Поиск по своим расшифрованным локально данным.

## 6. Дизайн — красиво, горско, современно, не китч

Визуальный язык **si**:
- Палитра: глубокий ночной зелёный `#0B1F1A`, камень `#2C3330`, тёплый шерстяной `#C4A574`, молоко `#F4EFE6`, акцент рубин-гранат `#8E1F2F`, золотая линия `#D7B36A`.
- Шрифты: свободные. Заголовки — геометрический гротеск с широкой гарнитурой; текст — читаемая антиква/гротеск с кириллицей и латиницей. Чеченский должен рендериться корректно (проверить глифы).
- Формы: мягкие карточки 20–28px radius, тонкая золотая линия 1px на ключевых действиях, много воздуха.
- Иконки: линейные, 1.5px, свои, не Material-копипаст.
- Древо: спокойная визуализация (не кислотный WebGL), фокус на читаемости 9 колен.
- Кошелёк: крупные цифры, без мем-графиков.
- Анимации: 180–240ms ease-out, никакой истерики.

Звук (оригинальный, короткий, тёплый, не сломанный glass-звук iOS):
- `ui_tap` — деревянный тихий удар 40–60ms
- `ui_success` — две мягкие ноты восходящие
- `ui_warn` — низкая струна
- `tx_sent` — короткий горный мотив 0.6s
- `invite_accepted` — тот же мотив с обертоном
- Громкость по системной, отдельный тогл «звуки si», haptics на iOS/Android

Доступность: Dynamic Type, VoiceOver/TalkBack на главных потоках, контраст WCAG AA.

Собери сразу:
- `design/tokens.json`
- `design/sounds/` (опиши генерацию тонов кодом, если нет ассетов)
- 5 ключевых экранов: Onboarding, Home, Silsila Tree, Wallet, Event.

## 10. API и офлайн

- Офлайн-первый: древо, архив, кошелёк-история локально.
- Синхронизация: CRDT или event-log с векторными часами для графа; конфликты родства не автомержатся — показывай людям.
- Транспорт: HTTPS + в будущем Noise/QUIC.
- Формат инвайта: `si://...` deep link.

Сервер MVP можно на Rust (`axum`), но он тупой: инвайты, события, релей шифротекста. Он не владеет деньгами и не владеет истиной рода.

- Ada пакеты с контрактами `Pre/Post/Invariant` хотя бы на ledger transfer и kinship acyclicity.

### Шаг D — UI
